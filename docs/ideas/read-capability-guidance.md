# Read and Verification Capability Guidance

Agents need more than command schemas. Before proposing a mutation they must know
which read establishes context, what authority owns the returned state, what it cannot
prove, how fresh it is, and when an apparent answer remains unknown.

Extend the existing capability catalog with a distinct read contract. Start with
interpretation coverage, business discovery, order explanation, commitments,
inventory, and operational exceptions. Keep reads non-mutating and describe their
roles in discovery, decision context, and post-effect verification.
