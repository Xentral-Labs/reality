# Research decisions

- Decision: retain existing inverse + optional replacement semantics and unchanged reservations. Rationale: core already provides atomic lineage/replay. Alternative rejected: editing original quantities or restoring reservations.
- Decision: correct the selected-replacement preview and add pure projected validation to the shared core validator. Rationale: current preview returns the prior original for replacement targets and omits replacement/identity validation. Alternative rejected: temporary Reality writes in a rollback simulation, or transport-owned stock rules.
- Decision: dedicated correction review/proof helper with early dispatch in the common proposal pipeline. Rationale: standalone movements and transfers do not have a mandatory delivery case. Alternative rejected: synthetic commitments or pretending correction is an ordinary shipment/receipt.
- Decision: quantity form preserves original supported fields; richer canonical intents remain exact, with explicit unsupported newer return-link guard. Rationale: no generic JSON editor or expanded return workflow is needed for this increment.
- Decision: existing action_id/event linkage and correction IDs prove outcomes. Rationale: no schema is necessary; correlation by matching quantity alone cannot prove ownership.
