# Research: Web UX Matrix Completion

## Decision 1: Version an exhaustive verification contract

**Decision**: `ux-matrix-v1` maps every actual route/nested destination to one matrix
surface, job, hierarchy, states, explanation behavior, and owner.

**Rationale**: Exact comparison detects omissions without becoming route/permission truth.

**Alternatives considered**: Documentation or screenshots alone cannot detect topology
drift; runtime generation would create a second authority.

## Decision 2: Remediate by user-job family

**Decision**: Group work into shared patterns, operations, finance/Evidence,
configuration, and support/traceability.

**Rationale**: Related pages share hierarchy and can be reviewed independently without a
wholesale client rewrite.

## Decision 3: Reuse reads and add narrow projections only

**Decision**: Reuse dashboard, exception, commitment, inventory, finance, document,
ledger, source, master-data, and Inspector services. Add output only for proven UX jobs.

**Rationale**: Most truth exists; Journal can use established ledger services.

**Alternatives considered**: Browser aggregation fails under pagination; stored UI
summaries violate Reality authority; broad endpoint expansion lacks proven use.

## Decision 4: Human visual approval plus executable behavior coverage

**Decision**: Use Node topology/state contracts, backend tests, builds, and a deterministic
desktop/mobile review worksheet. Human approval judges visual hierarchy.

**Rationale**: The repository has no browser automation dependency; adding one solely for
screenshots is not justified yet. Manual-only review cannot detect route drift.

## Decision 5: Add Journal; preserve Spec 029 Activity ownership

**Decision**: Add read-only Journal backed by existing ledger services. Map Activity as
separately owned and validate integration after Spec 029 merges.

**Rationale**: Journal is an explicit matrix job; Activity already has a numbered owner.

## Decision 6: Preserve one Inspector and settings hierarchy

**Decision**: Use the shared Inspector and Company/Data/Agents settings shell. Nested
destinations may fulfil matrix rows without new top-level routes.

**Rationale**: This preserves context and avoids duplicate detail logic or setup dashboards.
