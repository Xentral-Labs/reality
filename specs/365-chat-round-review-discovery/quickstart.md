# Validation Quickstart

Use isolated pytest PostgreSQL fixtures, not the user database. Run new shared
selection, HTTP, provider-loop and capability tests first; observe failing regressions
before implementation. Then run lint, spec check and docs generation/catalog check,
and the complete Quality workflow on the final PR head.

For live acceptance, use only the authorized synthetic company. Confirm that the
shipment page contains only matching movements before repeating the exact published
daily mission. Compare Chat statements with order_explain and retained movements.
Record whether each external-client test is actual scheduled, manual, unsupported
or blocked. Verify next run and pause from the client, then revoke test access and
retain original connections, company evidence and unrelated routines.
