# Durable design

Reuse immutable Sources for run configuration, incoming/local outgoing mail, acknowledgements and monitor evidence; use run-specific source namespaces and stable external identities. Lock the run source to serialize world/manual intake, never update it. Reuse ScheduledJob/Run timing, ownership and retry metadata. No schema/migration or new business-state authority. Short caller-owned transactions make external sessions see releases. The normal manual-order service retains its default commit behavior and gains an internal transaction-bound option.

Consistent monitoring compares retained source lines/raw movements with normal operational reads, checks lineage and balanced posting groups, and observes external tool execution without depending on fixture receipts. It does not derive expected quantities from the projection under test. Private future events remain inaccessible to the operator. The separate loopback live adapter has fixed company/run/owner scope; existing artifact viewer remains read-only/database-free. A trusted local mailbox CLI serves external code agents alongside their normal Reality connection. Manual preview does not write; injection and local reply require exact confirmation. No real email executor.

Shared simulator execution acquires the existing company lock before schedule/run/source locks. Manual injection acquires the same lock before run/source records, avoiding scheduler/control inversion. Near the mailbox bound, causal batches wait for acknowledgements rather than repeatedly failing or exceeding the bound.
