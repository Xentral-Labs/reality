# Frozen design reference

`reference.html` is a snapshot of the interactive HTML reviewed in the conversation.
It establishes the intended visual family and information architecture, not runtime
behavior or a requirement to implement every depicted module in the first increment.
The source remains `output/visualizations/reality-unified-ui.html`; later experiments
there must not silently redefine this specification's accepted reference.

## Preserve in the first increment

- A distinct application sidebar, clear active company and restrained shared chrome.
- Home as an operational overview, connected to work and review rather than an isolated
  collection of charts.
- Global Chat as a primary workspace, with business context and structured actions.
- The selected delivery's readable quantities, worklist and contextual assistant.
- Clickable quantity explanations and collapsed technical details.
- The same recognizable review/confirmation interaction at every supported action entry.
- Responsive behavior, useful whitespace, clear hierarchy and light/dark appearance.

## Intent from the conversation beyond the snapshot

The reusable action card must allow editing required inputs and resolving references,
not merely pressing the snapshot's fixed reservation button. Both reservation and
shipment must be reachable from case, company Chat and global discovery, with actual
proposal/recovery behavior. This is specified in US4 and US5.

## Do not transfer as production behavior

- Scripted Chat replies, fixed IDs, fictional company data and client-only confirmations.
- Browser-calculated authoritative stock, balance or fulfillment rules.
- Illustrative time series or metric formulas without proven shared-service coverage.
- Empty price/terms placeholders as substitutes for later real maintenance interfaces.
- The separate Playground sidebar entry as the final integrated-practice architecture.
- New product capability claims for later modules merely because the mockup draws them.

The screenshot is a design direction, not a pixel-perfect acceptance standard. The
implementation must use the actual product's shared controls and make accessibility,
localization and current business state work in this design family. Owner visual
acceptance is required for Home, Chat, delivery, review and result.
