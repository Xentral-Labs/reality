# %%TITLE%%

<PostMeta />

Hier steht die These, in zwei oder drei Sätzen, vor jeder Vorbereitung. Wer nach diesem Absatz
aufhört zu lesen, soll wissen, was behauptet wird — und widersprechen können.

Danach folgt die konkrete Situation, die das Argument trägt. Echte Mengen, ein benannter
Geschäftspartner, eine Ereignisfolge mit Daten. Abstrakte Datenmodell-Argumente reisen nicht; ein
Teilwareneingang mit anschließender Kundenänderung schon.

Diese Fassung wird geschrieben, nicht Wort für Wort übersetzt. Sie darf andere Beispiele verwenden,
solange sie dieselbe These vertritt.

## Warum die klassische Antwort bricht

Zeig das Scheitern an der Situation oben, nicht per Behauptung. Benenne, was das klassische System
speichert — und welche Frage es deshalb nicht beantworten kann.

## Was stattdessen gespeichert wird

Erklär das Reality-Verhalten und verlinke jede Aussage darüber auf die Seite, die sie belegt, zum
Beispiel [Grundlagen](/de/concepts/business-reality-guide/01-foundations) oder die
[die technischen Kataloge](/de/catalogs/).
