## Versioning and changes

Public Docs describes the current `main` contract unless a deployed release pins another revision.
Behavior changes begin in a numbered feature spec and update durable/public documentation where
needed. Git history and release notes are the changelog; breaking interface changes must be called
out explicitly in their feature and release material.
